# 技术文件起草（JSWJ_DraftbyDSH）使用指南

技术文件起草（JSWJ_DraftbyDSH），以下简称本插件。本页是本插件的使用说明，面向使用「技术文件起草」页面与助手的同事。所有文档与资料存放在本知识空间，出稿统一走 GY-F003 模板。

## 一、这是什么

本插件由三部分组成：

- 一个 DSH 插件：提供 9 个工具与分步任务页面
- 一个 Skill：约束起草与预审的业务流、门禁和写回格式
- 本知识空间：存放模板、参考资料、草稿与出稿

## 二、从哪里开始

1. 打开桌面端 DSH，左侧栏点「技术文件起草」
2. 任务列表点「新建技术文件」或「新建预审」
3. 按步骤填写，每步门禁通过才能进入下一步

任务状态保存在本机任务库，刷新、重开、换会话都不会丢；同一任务号可以在任务列表继续。任务列表按「待处理 / 进行中 / 已完成」分组，有未处置意见或待确认修订的任务会进入「待处理」。已完成的步骤可直接点回查看或修改，进度不会重置。

## 三、起草：D1–D8

### D1 基本信息

填文件名称、选文件类型与密级，编号可空。名称做重名检测；类型决定章节模板与评审单，选定后不可改。

### D2 文档属性

选层级、板块、归档位置；归档位置选 Polarion 时，填项目空间名称（如 `GAC_A6_T0`）。目录由属性推导：技术资料起草库 / {层级} / {板块} / {文件类型} /，出稿时自动创建。

### D3 参考资料

粘贴飞书云文档链接点「解析」，或直接上传 docx / md。上传的文件会留存到 资料库 / {层级} / {板块} /，并抽出纯文本供助手读取；至少一份解析成功才能锁定。

### D4 大纲与纲要

系统给出章节树。必备章锁定；一级、二级章节填要点，要点框会随内容自适应高度、可换行；也可以点「让助手拟稿」先出一版初稿，确认后再改；三级以下可留空。

### D5 生成

点「交给助手生成」，助手逐章生成，并在同一回合内自动自检、修订到没有严重项，再把成稿写回任务。回到本页点「刷新」，进入成稿确认。

### D6 成稿确认

页面直接给成稿，不需要逐步确认自检和修订。点「生成预览稿」在知识库里看 Word，写下意见后点「提交意见并修订」，助手只按意见定向修改。满意后点「确认成稿，去出稿」。

### D7 出稿

出稿把同一份成稿按正式文件名（编号-名称.docx）落位到第 2 步的目录，并删除旧草稿文件，不生成两份；完成后返回文件节点链接。

## 四、预审：R1–R5

### R1 确认开始

确认范围与预计耗时，确认即建立预审任务。

### R2 类型与评审单

选评审类型，系统加载对应评审单并冻结版本；类型与评审单必须匹配。

### R3 文件与资料

提供受审文件（必需）。参考资料可选；缺失时相关检查项标「缺依据」。

### R4 预审

点「交给助手预审」，助手按评审单审内容、按模板审格式，把意见写回任务。

### R5 意见与修订

查看意见清单，按维度分组；每条必须「采纳 / 驳回 / 改写」，不能留待定，驳回要填理由。全部处置后才能存档意见书或让助手协助修订。预审不输出通过或不通过的结论。

## 五、门禁

- G1：名称非空、类型与密级已选
- G2：层级、板块、归档位置齐备，目录可创建
- G3：至少一份参考资料解析成功
- G4：大纲覆盖必备章节，一二级要点齐备或标注「AI 拟稿」
- G5：全部章节生成完成
- G6：成稿已生成并确认
- G7：文件已出稿，回执已生成
- Q1：已确认开始
- Q2：评审类型与评审单匹配
- Q3：受审文件解析成功
- Q4：预审已产出意见
- Q5：意见书已存档

## 六、目录与命名

- 资料库：技术资料起草库 / 资料库 / {层级} / {板块} /
- 起草库：技术资料起草库 / 起草库 / {层级} / {板块} / {文件类型} /
- 出稿库：技术资料起草库 / 出稿库 / 飞书审批 / {层级} / {板块} / 或 Polarion / {项目空间} /
- 预审存档：技术资料起草库 / 出稿库 / 预审 / {评审类型} / {任务号} /
- 起草中命名：{名称}-v{版本}.docx
- 出稿命名：有编号 {编号}-{名称}.docx；无编号 {名称}.docx

## 七、工具

- jswj_ping：检查凭据、空间、Python 与模板
- jswj_wiki_list：列出节点下的子节点
- jswj_doc_read：读取在线文档正文
- jswj_wiki_create：新建 docx 节点
- jswj_doc_append：追加内容，支持少量 Markdown
- jswj_render_docx：Markdown 渲染为 GY-F003 Word
- jswj_publish_docx：上传并移入知识库
- jswj_task_get：读取任务状态
- jswj_task_update：写回生成、自检、预审、修订结果

## 八、交给助手时发生什么

页面只保存任务与决策。生成、自检、修订、预审点「交给助手」后：

1. 在「技术文件起草」工作区新建会话（首次自动创建，目录 `~/技术文件起草`），标题按「文件名 步骤名」命名，例如「文档测试 1 大纲与纲要草拟」「文档测试 1 正文生成」「文档测试 1 草稿自检与修订」
2. 助手读取任务、执行本步
3. 助手把结果写回任务
4. 回页面点「刷新」继续

每步对应一个会话，任务里记录了会话 id；再次点该步的「交给助手」会打开原会话继续，需要另开一个时点「新建会话」。正文以任务里的 `draft.markdown` 为准，换会话不会丢内容。

助手不会越过当前步骤做后面的工作；任务文件只通过工具读写，不要手工修改。

## 九、常见问题

- 页面空白或打不开：先刷新；仍不行看「设置 - 插件」里是否启用
- 按钮点了没反应：看页面底部错误提示；确认助手会话是否创建成功
- Word 版式异常：用 Word 或 WPS 打开核对，LibreOffice 与模板有已知差异
- 发布失败：检查应用是否为知识空间成员，以及目标父节点的编辑权限
- 资料解析失败：确认链接是 docx 在线文档；file 类型节点不能读正文

## 十、当前限制

- 单文件不超过 20 MB
- 只读 docx 在线文档
- 大纲模板内置两份：需求规范、技术方案
- 预审意见的逐条处置仍是简化版，当前提供存档与助手协助修订

## 十二、字体安装

页面打开时会自检 HarmonyOS Sans SC。未安装时，任务列表顶部出现「安装字体」按钮：本插件从字体目录复制 6 个字重到用户字体目录并写注册表，重启 DSH 后生效。字体目录优先取配置项 `fontDir`，其次桌面「鸿蒙字体（对外仅可用该字体）」。字体文件不随插件分发。

## 十三、版本

0.3.5。代码仓库由管理员维护，配置与凭据不写入本文档。

## 附：删除任务

任务列表卡片和任务详情页都提供「删除」。删除前需二次确认；删除只移除任务记录，已出稿文件与上传资料不受影响。
